## Migration Planning Notes

- Same-ID migration into one v3 contract will collide for any token ID that exists on more than one source contract.
- Escrow/wrapper migration can avoid re-uploading bytes, but v3 must record the source contract for migrated chunks.
- Existing v1/v2 token IDs should be treated as contract-qualified IDs until migrated.
- If collisions exist, migration needs either a collision policy, separate v3 namespaces, or non-same-ID remapping with an explicit source map.
